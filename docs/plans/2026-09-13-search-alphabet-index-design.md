# 検索画面 A〜Zアルファベットインデックス 設計

## 背景

Niagara Launcher の検索／アプリ一覧に近い体験にしたいという要望。調査の結果、検索画面（`AppDrawer.kt`）はすでに `LazyColumn` による縦一列リスト表示（アイコン代替の単色ブロック＋アプリ名）になっており、「グリッド→リスト」の変更は現状で満たされていた。したがって今回のスコープは、リストへの **A〜Zアルファベットインデックスナビゲーションの新規追加** のみとする。

## スコープ

1. 検索結果一覧の右端にA〜Z（＋日本語名・記号・数字始まり用の「#」）を縦に並べたインデックスバーを追加
2. タップ／ドラッグで対応する文字の位置までリストをジャンプ
3. ドラッグ中は選択中の文字を画面中央に大きくオーバーレイ表示
4. 検索結果が20件未満の場合はインデックスバーを表示しない

対象外（今回は見送り）:
- ホーム画面のUI・レイアウト変更
- 検索ロジック（`AppRepository`/`AppFilter`/`AppListViewModel`）の変更
- 実アプリアイコンの復活（現状の単色ブロックを維持）

## アーキテクチャ

- 新規ファイル `ui/AlphabetIndexBar.kt` を追加。ステートレスなComposableとして実装し、既存の検索ロジック層（`AppListViewModel`, `AppRepository`, `AppFilter`, `AppInfo`）には一切手を入れない。
- `AppDrawer.kt` を修正し、既存の `LazyColumn` を `Row` で包んで右側に `AlphabetIndexBar` を条件付き（`apps.size >= 20`）で配置する。

## コンポーネント設計

### `AlphabetIndexBar`

- A〜Z + `#`（日本語名・記号・数字始まりの共通カテゴリ）を縦に並べた固定幅のバー
- `pointerInput` でタップ／ドラッグを検出し、バー内のY座標を27分割した位置から対象の文字を算出して `onLetterSelected: (Char) -> Unit` を呼ぶ
- ドラッグ範囲がバーの上下端を超えた場合は先頭/末尾の文字にクランプする
- ドラッグ中は選択中の文字を画面中央に大きくオーバーレイ表示する（`activeLetter` 状態を保持）
- 既存テーマ（`NothingTypography`のモノスペースフォント、黒/白/グレー系の配色）をそのまま流用し、新しい色トークンは追加しない

### `AppDrawer` 側の変更

- 現在の `apps: List<AppInfo>` から `remember(apps)` で「文字→先頭インデックス」のマップ（`Map<Char, Int>`）を算出する純粋関数を用意する
- 該当する文字が存在しない場合は、後方に近い文字のインデックスへフォールバックする（後方に何もなければ最後のインデックス）
- 選択された文字に対応するインデックスへは、`LazyColumn` と共有する `LazyListState` を使って `scrollToItem` でジャンプする

## データフロー

ドラッグ位置 → 文字を算出 → 文字→インデックスのマップから対象位置を取得 → `LazyListState.scrollToItem` でリストをジャンプ。検索ロジック（Repository/Filter/ViewModel）は経由せず、既存の `visibleApps`（アルファベット順ソート済み）の並び順をそのまま利用する。

## エッジケース

- 検索結果が20件未満 → インデックスバー自体を描画しない
- ドラッグがバーの上下端を超えた場合 → 先頭/末尾の文字にクランプ
- 該当文字なし → 直近の文字（後方優先、なければ最後）にフォールバック

## テスト方針

- 「文字→インデックス」マッピングとフォールバックロジックを純粋関数として切り出し、JUnitでテストする（完全一致・フォールバック・「#」カテゴリの境界値など、`AppFilter`/`IconPalette`と同じ方針）
- 実機/エミュレータでの動作確認（20件以上でバー表示、ドラッグでジャンプ、ホーム画面が影響を受けていないことの確認）

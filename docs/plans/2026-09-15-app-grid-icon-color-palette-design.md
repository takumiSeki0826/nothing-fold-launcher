# ホーム画面アプリ一覧の配色パターン 設計

## 背景

ホーム画面のアプリ一覧（2行×4列グリッド）に、ランチャーのメインカラー4色（黒 `#000000`・白 `#FFFFFF`・グレー `#8A8A8A`・アクセントの赤オレンジ `#D1432B`）を使った配色パターンを導入したいという要望。

以前は `IconPalette.kt` に `index % 4` でパレットを循環させる仕組みがあったが、4列グリッドでは同じ列が常に同じ色になり単調になる問題があった。またその仕組みは直近の作業（未コミット）で「全アイコン黒背景＋アクセント枚縁の統一デザイン」に置き換えられた。

**方針転換（初期設計からの変更）**: 当初は「位置ベース」「識別ベース」で自動的に色を割り当てるモードを検討したが、要望を確認した結果、**ユーザーがタイルごとに手動で4色から選ぶ**方式に変更した。自動割り当てロジック（`colorForSlot`、`IconColorMode`、モード切り替えの設定ダイアログ）は導入せず、削除済み。

## 配色ロジック

各アプリタイルの色は**アプリ（パッケージ名）に紐づけて手動で選択・保存**する。並び替えても同じアプリは同じ色を保つ。

- 色を選んでいないアプリはデフォルトでグレー `#8A8A8A`（枚縁を廃止したため、黒背景だと画面の黒背景に同化してタップ範囲が見えなくなるのを避けるため）。
- 選択可能な4色: 黒・白・グレー・アクセント（赤オレンジ `#D1432B`）。

## 見た目の変更点

- 変わるのは**アイコンタイルの背景色のみ**。
- **枚縁は廃止**（従来のアクセント色の枚縁は削除。背景色のみで表現する）。
- ラベルの文字色は常に白（ラベルはタイルの下に配置され、背景色と接していないため無関係）。

## 色の選択UI

- 既存のアプリ長押しメニュー（`AppContextMenu`、お気に入り切替・非表示・リネームがあるメニュー）に「Change color」項目を追加。
- 選択すると4色のスウォッチ（円形）を並べた小さなダイアログ（`IconColorPickerDialog`）が開き、タップした色がそのアプリに即時反映・保存される。

## 永続化

`HomeKnobAssignmentStore.kt` と同じ `SharedPreferences` パターンで、パッケージ名→選択色（enum名の文字列）を保存する `AppIconColorStore` を新規作成する。

## 実装ファイル構成

### 新規
| ファイル | 役割 |
|---|---|
| `ui/IconPalette.kt` | `IconPaletteColor` enum・`colorValue()`（Composeカラーへのマッピング）・`iconBackgroundColor()`（未選択時は黒にフォールバック） |
| `data/AppIconColorStore.kt` | パッケージ名→選択色のSharedPreferences永続化 |
| `test/.../IconPaletteTest.kt` | パレット計算のユニットテスト |

### 変更
| ファイル | 変更内容 |
|---|---|
| `ui/HomeScreen.kt` | `AppIconTile` から枚縁を削除。`AppGrid`/`AppIconTile` は `iconColorFor: (AppInfo) -> IconPaletteColor?` を受け取り背景色を決定 |
| `ui/AppContextMenu.kt` | 「Change color」項目、および`IconColorPickerDialog`（4色スウォッチ選択）を追加 |
| `MainActivity.kt` | `AppIconColorStore` の読み込み・保存、選択中アプリのstate、`IconColorPickerDialog`の表示を配線 |

## テスト方針

`IconPaletteTest.kt` で以下を検証:
- 4色それぞれが期待通りのCompose Colorにマッピングされること
- 色未選択（`null`）の場合は黒にフォールバックすること

実機での手動確認:
- アプリ長押し→「Change color」→スウォッチ選択でアイコン背景が即時変わること
- 折り畳み時・展開時（12枠）両方で反映されること
- 端末再起動後も選択した色が保持されること（永続化の確認）
- アプリ起動・お気に入り切替・非表示・リネームなど既存操作にregressionがないこと

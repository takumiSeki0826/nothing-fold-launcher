# ホーム画面 天気ウィジェット表示 設計書

## 背景

ホーム画面（`ClockRow`）には現在、時計とwifi/バッテリーなどのステータス表示（`StatusIcons`）のみが並んでいる。ここに現在地の天気情報（気温・天気アイコン・湿度・降水確率）を追加表示したい。展開時（大画面）・カバー画面（折りたたみ時）の両方に反映する。

## 1. パーミッション・位置情報取得

- `AndroidManifest.xml` に `ACCESS_COARSE_LOCATION` を追加する（気温表示目的のため高精度な `ACCESS_FINE_LOCATION` は不要）。
- パーミッションのリクエストは、ランチャー初回起動時（`MainActivity`起動時）に自動で行う。拒否された場合は天気ウィジェットを表示しない（他機能には影響しない）。
- 位置情報の取得には、新規ライブラリ依存を避けるため Android 標準の `LocationManager` を使う。
  - まず `getLastKnownLocation()` で `NETWORK_PROVIDER` → 取れなければ `GPS_PROVIDER` の順に既知の位置を確認する。
  - 既知の位置が無い場合のみ、単発の位置更新（`requestSingleUpdate`相当）をリクエストする。気温目的で高精度・高頻度な位置取得は不要なため、GPSの常時使用は避ける。

## 2. データ取得・キャッシュ

- 新規クラス `WeatherController`（`ui/StatusIconsController.kt` と同様の構成）を追加し、`MainActivity` で生成、`DisposableEffect`でライフサイクル管理する。
- 状態は `StateFlow<WeatherState?>` として公開し、`HomeScreen` にpropsとして渡す（`WeatherState`は気温・天気コード・湿度・降水確率を保持するdata class）。
- ホーム画面が表示されるたびに位置情報と天気を確認する。前回取得から **30分以内** ならキャッシュ済みの値をそのまま使い、超過していればバックグラウンドで再取得する。
- 天気データの取得元は **Open-Meteo**（`https://api.open-meteo.com/v1/forecast`、APIキー不要）。緯度経度をクエリパラメータとして渡し、気温・WMO天気コード・湿度・降水確率を取得する。
- 通信には新規ライブラリを追加せず、標準の `HttpURLConnection` + `org.json` でリクエスト・パースを行う（単発GETのみのため、Retrofit/OkHttp等の導入は見送る）。
- WMO天気コード → 表示用アイコン・ラベルへの変換テーブルを用意する。

## 3. UI・レイアウト

- 新規 Composable `WeatherWidget.kt` を追加する。
  - 1行目: 天気アイコン＋気温
  - 2行目: 湿度・降水確率（補足情報として小さめのテキスト）
- `HomeScreen.kt` の `ClockRow`（現状: `Clock`（左, weight(1f)）と `StatusIcons`（右）を`Row`で並べたもの）を、右側を`Column`化した構造に変更する：
  - `Row( Clock(weight=1f), Column( StatusIcons(), WeatherWidget() ) )`
  - `StatusIcons`が上、`WeatherWidget`がその下に来る（＝現状のwifi/充電表示は相対的に少し上へ、その下に天気が並ぶ）。
- `ClockRow`は展開時・カバー画面共通のComposableのため、この変更のみで両画面に反映される。呼び出し側（展開時: 111行目付近、カバー時: 216行目付近）のスペーシングは、天気ウィジェット追加後の見た目を見て微調整する。
- 天気データが無い場合（未取得中・パーミッション拒否・取得失敗）は `WeatherWidget` を丸ごと非表示にする。この場合 `StatusIcons` は現状通りの位置に収まる。

## 4. エラーハンドリング

- 位置情報取得失敗・ネットワークエラー・パース失敗は、いずれも「天気データなし」として扱う。例外はcatchしログのみに留め、ユーザーへのエラー表示は行わない。
- パーミッションが拒否されている場合は、そもそもAPI呼び出しを行わない。

## 5. テスト方針

- WMOコード→表示アイコン/ラベルの変換ロジックと、キャッシュ有効期限（30分）判定ロジックは純粋関数として切り出し、ユニットテストを書く。
- 実機（Galaxy Z Fold8）で以下を確認する:
  - 展開時・カバー画面時の両方で天気ウィジェットが正しい位置に表示される
  - 位置情報パーミッションを許可した場合／拒否した場合の両方の見た目
  - 機内モードなど通信不可時に天気ウィジェットが表示されない（クラッシュしない）こと

## スコープ外

- 複数日の予報表示
- 地点の手動設定・切り替えUI
- 天気に応じた壁紙・テーマ連動
